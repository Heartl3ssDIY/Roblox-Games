# Rock Lii animation integration proposal

These files are local proposals derived from the live `Anime Combat Units` Studio place (place ID `111313211501470`) on 2026-09-29. They have **not** been written to Studio. `CombatController.proposed.luau` and `AttackTimeline.proposed.luau` are complete replacements of the current live ModuleScripts with the small changes described below. `RockAnimationPlayer.luau` is a new ModuleScript to put under `ReplicatedStorage`.

Both reviewed KeyframeSequences have been published under Deus Invictus Studios and their numeric asset IDs are present in `RockAnimationPlayer.ASSET_IDS`. Keep the published animation's R6 hierarchy; both models have the six matching Motor6Ds and a Humanoid Animator. The module starts a nonblocking asset prefetch when required and `CombatController.run` prepares tracks on each deployed Rock rig before combat begins. The final export manifest says the Drunken Fist root turn is folded into the Torso pose and the HumanoidRootPart pose stays identity. The live combat path moves the model pivot through the arena; the animation rotates the Torso locally, so both motions can play together without moving the gameplay pivot twice.

`AttackTimeline.proposed.luau` maps the three normal impacts at Blender frames 9, 20 and 33 to elapsed times `8/30`, `19/30` and `32/30` seconds in the 1.5-second attack. Blender frame 1 is elapsed time zero. The mastery form retains its existing four-hit times and one-second cooldown. There is no reviewed four-hit mastery clip, so `playAttack` intentionally leaves mastery attacks unanimated rather than showing three punches for four damage events. A dedicated four-hit clip is needed to complete mastery visuals.

The approved normal attack's wrist reaches about 1.79–1.83 studs forward at the three contacts. Adding a typical enemy torso half-width and the 0.45-stud fist radius supports about 3 studs of center-to-center reach. `CombatController.proposed.luau` therefore gives Rock alone a 3-stud acquisition range and a small `+0.15` hit tolerance; the old generic 7-stud category plus `+0.75` hit tolerance visibly let him punch air. The second normal punch releases its cue from the left palm, and the mastery four-hit cue alternates right/left. These are Rock-specific changes only.

`CombatController.proposed.luau` starts the normal animation when Rock begins a base attack, starts Drunken Fist for either Rock model when the ability begins, synchronizes playback to the pausable match clock each render frame, and cleans up tracks on knockout, round interruption, or cancellation. The authored Drunken Fist clip spins in place while `stepRockAbility` carries the unit front → mid → back → start over seven seconds. Its fixed `simPivot` facing stays fixed so the animation's Torso spin is not doubled. The existing route, seven-second immunity, VFX and SFX remain.

The proposal replaces the current 3.2-stud moving-pivot touch model with animated fist contacts for the **full seven seconds**. Rock's model pivot and animation clock update in `PreAnimation`, independently of `RenderStepped`; Animator then writes the new `Motor6D.Transform`, and `PreSimulation` samples both posed R6 fists. This order also works in the headless Studio playtest where `RenderStepped` did not fire. Other units keep their existing RenderStepped pivot updates. `palm(unit, right)` computes each posed arm end, and the code checks its movement against opposing torso spheres. Each hand has its own per-enemy contact state. Entry deals 50 damage once; remaining overlapped cannot deal frame-by-frame damage; exiting an expanded hitbox clears that hand's contact so a later re-entry deals another 50. Both hands can independently hit the same target. The first sampled pose establishes a baseline and does not cause an instant static-overlap hit. The contact hitbox uses a 0.45-stud fist radius plus half the target torso's horizontal size, with 0.4-stud exit padding. For frame gaps up to 0.1 seconds and hand-relative travel up to 3.5 studs, previous-to-current positions are swept so a brief pass-through still registers; larger gaps use the endpoint only to avoid long-chord false hits. The 3.5-stud cap exceeds the 2.9-stud diameter of a typical 1.45-stud contact sphere, allowing an outside-to-outside pass-through. These are tuning values to check in Studio playtests. Contact damage is independent of visual-effects settings. Since the existing combat simulation is local-client driven, this follows its current architecture but would need a server-authoritative redesign if multiplayer combat becomes shared.

`UnitViewport` explicitly skips `UnitPreviewAnimator.attach` for both Rock models. That is appropriate for this combat-only integration: `UnitPreviewAnimator` stops tracks started by `Animator` on its own preview rigs, so the new imported tracks must not be routed through it. A later idle/preview implementation can be separate.

Validation in Studio: play one normal base attack and confirm three distinct damage ticks at the three hand contacts, one 1.5-second loop, and no animation doubling on the mastery rig; trigger Drunken Fist and confirm seven-second Torso rotation, arena travel, return to starting pivot, immunity, independent 50-damage events from both fists, pause/resume, knockout cleanup, and next-round track cleanup. Specifically keep one fist overlapping an enemy for several rendered frames and verify one hit, move it outside the expanded hitbox and back for a second hit, check the other fist can score its own hit, and verify a swept pass-through at normal frame rate. A frame gap above the sweep limit may miss a brief contact by design. Test both local and opponent views if animations must replicate to other players: Roblox requires server-started NPC animations for cross-client replication, while this CombatController is client-driven.

With a 2×2×1 torso, contact entry radius is 1.45 studs and exit radius is 1.85. These simple relative-position cases make the hand-entry logic testable in a Studio playtest or a small geometry harness:

| Case | Hand-center samples relative to target | Expected |
| --- | --- | --- |
| Baseline overlap | first sample at x=1.0 | 0 damage; contact starts latched |
| Held overlap | x=1.0 → 1.2 → 1.7 | 0 further damage; 1.7 remains inside exit radius |
| Leave and return | x=1.9 → 1.2 | exit unlatches, then one 50-damage contact |
| Other hand | left hand enters independently while right is latched | another 50 damage |
| Brief crossing | x=−1.6 → +1.6 in 0.033s | one 50-damage swept hit, with no latched end contact |
| Long jump | x=−2.0 → +2.0 in 0.033s | no hit; 4-stud chord exceeds sweep cap |
| Low frame rate | x=−1.6 → +1.6 in 0.2s | no swept hit; gap exceeds time cap |
| Paused | no `PreSimulation` contact sample while MatchClock is paused | no damage |
